= Namco FCA2 PCB
:toc:
:icons: font

This IO PCB is used in several Namco games around the early 2000s including but not limited to:

* Wangan Midnight: Maximum Tune
* Wangan Midnight: Maximum Tune 2
* Wangan Midnight: Maximum Tune 3
* Mario Kart Arcade GP
* Mario Kart Arcade GP2
* Ridge Racer V

[cols="1h,2"]
|===
|Main MCU |Fujitsu MB90F574A
|Sub MCU |PIC16F84
|Chainable |Yes ^1^
|Players |1
|Digital |16
|Analog |7
|Rotary |2
|Digital Out |6 ^2^
|Analog Out |2 ^2^
|===

.Notes
. Whilst it supports chaining, most of the time the USB-A connector is not populated, nor is the JST-XH 4-pin connector which also acts as the downstream port.
. All outputs are *disabled* until they are enabled using a manufacturer specific command (see <<enable-outputs,"Enable Outputs">> below).

The PIC MCU handles the coin slots by monitoring the coin counter lines and not accepting coin inputs if the coin meter is not connected.

[#dip-switch]
== DIP Switch

The FCA has a bank of 6 DIP switches which change aspects of the IO board:

[%header,cols="1,8"]
|===
|DIP Sw |Function

|1 |Do not require output enable command - This will keep the outputs disabled until _any_ JVS message is received by the IO board, where they will stay enabled all the time.
|2 |Do not require output enable command - Same as above but outputs will be disabled again on a JVS Reset command.
|3 |Use 8 digital GPO instead of 6 + 2 PWM - The IO will not report more GPOs, you must read the DIP switch to know you can send 8 GPO states. Analog Out 3 will become GPO 1.
|4 |
|5 |
|6 |Enable the FCA Monitor on UART0
|===

== Misc Commands

Namco I/O boards have some undocumented extended JVS commands that offer more features. These are all prefixed with JVS command `0x70` which is manufacturer specific.

=== 0x02 - Read Program Memory

This command returns bytes from the Main MCU's program memory, starting at `0xFF0000`. Format is:

[%header,cols="1,4"]
|===
|Payload Byte |Description

|0 |`0x70`
|1 |`0x02`
|2 |Index
|===

Response from the Main MCU is:

[%header,cols="1,4"]
|===
|Payload Byte |Description

|1 |JVS Report
|2 |Data 0
|3 |Data 1
|4 |Data 2
|5 |Data 3
|6 |Data 4
|7 |Data 5
|8 |Data 6
|9 |Data 7
|===

NOTE: This does *not* read the entire flash rom out, only 64KiB. Luckily, all of the IO board's firmware resides in this high bank of memory (On FCA2/FCAF11).

=== 0x03 - Get DIP switches

This command returns the status of SW1 on the I/O board. Used to see whether commands should be issued differently in the case of outputs.

=== 0x04 - Unknown - Firmware date?

This command returns two bytes of `0xFF` but has seemingly no other use. The word at `0xFFBC31` (the source of the bytes returned) is set to `0xFFFF` at power up and then not touched again.

[#enable-outputs]
=== 0x18 - Enable Outputs

The outputs of the FCA are disabled by default and neither GPO nor Analog Out commands will result in a change until you send this command. This was possibly done due to concern that an output could be attached to something requiring monitoring to avoid injury.

Format is:

[%header,cols="1,4"]
|===
|Payload Byte |Description

|0 |`0x70`
|1 |`0x18`
|2 |`0x50`
|3 |`0x4C`
|4 |Mode
|5 |Time
|===

[%header,cols="1,4"]
|===
|Mode |Description

|`0x00` |Outputs are instantly turned enabled
|`0x01` |Outputs are enabled after a short delay
|`0x14` |Outputs are enabled after a delay specified in byte 5
|===
